# カタン実装用ルール仕様（ベースゲーム・3〜4人）

> **目的**: Next.js + Python で作るカタンアプリのルール実装、テスト、AIの共通参照資料。
> この文書は公式ルールブックを転載するものではなく、実装のために要約・構造化した仕様である。

## 1. 対象範囲と方針

### 対象

- カタンのベースゲーム（拡張なし）
- 3〜4人対戦。ただしアプリの初期目標は4人固定で、人間とAIを任意に組み合わせる
- 通常の対局ルール。大会の持ち時間・審判・マナー規定はゲームエンジンの対象外
- 資源、建設、交易、盗賊、発展カード、最長交易路、最大騎士力、勝利点を含む

### 対象外（将来の拡張候補）

- 5〜6人拡張、航海者、都市と騎士、その他の拡張
- 観戦モード、チャット、ランキング、オンライン対戦の切断復帰
- 大会固有の時間制限・失格処理

### 採用するルールの優先順位

1. CATAN公式の現行ベースゲームルールブック
2. 同公式のベースゲームFAQ
3. アプリ固有の決定（この文書の「実装上の決定」）

指定された [GPの公式ルールページ](https://www.gp-inc.jp/catan/rule/rule.html) は日本の大会用補足として参照する。
指定された [catan.orgのページ](https://catan.org/rule.html) はページ自体が2006年度版であり、2010年以降の統一ルールより前の資料であることを明記している。そのため、現行アプリの基本規則には採用せず、旧ルールの比較資料としてのみ扱う。

なお、実在の製品名・カード名・アートワーク等の権利は各権利者に帰属する。公開・配布をする段階では、ブランド利用、画像、ルールブックの扱いを別途確認する。

## 2. ゲームの目的

自分の手番中に**10点以上**の勝利点を獲得し、勝利を宣言したプレイヤーが勝者になる。

| 得点源 | 点数 |
| --- | ---: |
| 開拓地 | 1 |
| 都市 | 2 |
| 最長交易路 | 2 |
| 最大騎士力 | 2 |
| 勝利点の発展カード | 各1 |

各プレイヤーは初期配置の開拓地2つにより、ゲーム開始時点で2点を持つ。勝利点の発展カードは伏せられているので、通常は公開得点と内部の実得点を分けて管理する。

## 3. 盤面とコンポーネント

### 3.1 資源と地形

| 地形 | 産出資源 | 枚数 |
| --- | --- | ---: |
| 森林 | 木材 | 4 |
| 丘陵 | レンガ | 3 |
| 牧草地 | 羊毛 | 4 |
| 畑 | 小麦 | 4 |
| 山地 | 鉱石 | 3 |
| 砂漠 | なし | 1 |

資源カードは各種類19枚、合計95枚を共通の銀行（供給）として管理する。資源は有限であり、捨てた資源や建設費は銀行へ戻る。

### 3.2 盤面の座標

盤面は六角形タイル（`hex`）、タイルの交点（`vertex`）、交点を結ぶ辺（`edge`）で表す。

- 開拓地と都市は `vertex` に置く
- 道は `edge` に置く
- 各 `vertex` は最大3つの地形タイルに接する
- 各 `edge` には道を1本だけ置ける
- 港は海岸の特定の `vertex` に関連付ける

UI上の見た目と、ルール判定用のグラフ構造は分ける。判定に必要なのは「どのタイル・辺・交点が隣接しているか」であり、ピクセル座標は必要ない。

### 3.3 数字チップ

砂漠を除く18タイルに、次の数字を1つずつ割り当てる。7は数字チップに含めない。

```text
2, 3, 3, 4, 4, 5, 5, 6, 6, 8, 8, 9, 9, 10, 10, 11, 11, 12
```

6と8は出やすい数字であり、標準の可変配置ではこれらが隣接しないようにする。

### 3.4 港

標準盤には9港を配置する。

- 任意の同種資源3枚を1枚へ替えられる一般港: 4個
- 木材、レンガ、羊毛、小麦、鉱石の各資源を2枚から1枚へ替えられる専門港: 各1個

港の交易権は、その港に接する海岸交点に自分の開拓地または都市があることで得る。

### 3.5 プレイヤーごとのコマと発展カード

プレイヤーごとの上限は、道15本・開拓地5個・都市4個。使い切った種類は追加で建設できない。

発展カードは25枚で、以下の内訳で初期化する。

| 種類 | 枚数 | 効果の要約 |
| --- | ---: | --- |
| 騎士 | 14 | 盗賊を移動し、対象からランダムに資源1枚を得る |
| 街道建設 | 2 | 建設条件を満たす道をコストなしで2本置く |
| 発見（豊作） | 2 | 銀行から任意の資源を合計2枚得る |
| 独占 | 2 | 資源種を1つ宣言し、他プレイヤー全員からその資源を全て得る |
| 勝利点 | 5 | 1点。通常は非公開 |

## 4. 初期化と初期配置

### 4.1 盤面の作成

最初の実装では、検証しやすい**固定盤面**を1つ用意する。可変盤面はその後に追加する。

可変盤面では次を満たす。

1. 19枚の地形をランダムに配置する
2. 砂漠に盗賊を置く
3. 18個の数字チップを砂漠以外に配置する
4. 6と8が隣接しないことを検証する
5. 9個の港を海岸に配置する

再現可能なテストやAI対戦のため、盤面生成には `seed` を保存する。

### 4.2 配置順

開始プレイヤーを決め、時計回りに初期配置する。各配置は「開拓地1つ、直結する道1本」の順とする。

```text
1番 → 2番 → 3番 → 4番 → 4番 → 3番 → 2番 → 1番
```

各プレイヤーは合計で開拓地2つ、道2本を置く。2つ目の開拓地に接する資源地形から、開始資源を各1枚ずつ受け取る。都市は初期配置では使わない。

初期配置の開拓地は通常の「自分の道に接続する」条件の例外だが、交点が空いていることと距離ルールは守る。初期の道は、その直前に置いた開拓地の辺に置く。

### 4.3 距離ルール

開拓地・都市がある交点に隣接する3交点には、誰も新しい開拓地を置けない。言い換えると、道1本分しか離れていない2交点に建物を並べることはできない。

## 5. 手番の流れ

通常の手番は、次の流れで処理する。

```text
手番開始
  ├─ （任意）発展カードを1枚使う
  ├─ ダイスを2個振る
  ├─ 出目の処理
  │    ├─ 2〜6, 8〜12: 資源を生産
  │    └─ 7: 手札破棄 → 盗賊移動 → 資源を1枚奪う
  ├─ 交易・建設・発展カード使用（任意の順序）
  ├─ 勝利条件を確認・宣言
  └─ 手番終了 → 次プレイヤーへ
```

通常の基本ルールでは、資源生産の後に交易、その後に建設を行う。アプリでは操作性のため、ダイス処理を完了した後は交易・建設を好きな順で繰り返せる「統合フェーズ」を採用する。これは公式ルールブックが上級者向けに許容する運用に沿う。

発展カードは自分の手番中に使う。騎士・進歩カードは合計で手番に1枚までで、購入した手番には使えない。勝利点カードは勝利に必要な点数へ届く場合に公開できる。

## 6. 資源生産と盗賊

### 6.1 2〜6、8〜12が出た場合

出目と同じ数字の全地形が生産する。ただし盗賊が置かれている地形は生産しない。

- その地形に接する開拓地1つごとに、所有者は対応資源を1枚得る
- 都市は対応資源を2枚得る
- 同じプレイヤーが同一地形に複数の建物で接していれば、その分を加算する
- 生産は手番プレイヤーだけでなく、条件を満たすすべてのプレイヤーに行う

資源の山が不足し、複数のプレイヤーへの必要な配布を満たせない資源種は、その出目では誰にも配布しない。資源種ごとに独立して判定する。銀行不足の細部は版で解釈の余地があるため、実装時はテストで明文化する（推奨: 受給者が1人だけなら銀行に残る分を全て渡し、それ以外は配布しない）。

### 6.2 7が出た場合

7では通常の資源生産をしない。以下を順に完了するまで、他の行動へ進めない。

1. 資源カードを8枚以上持つ全プレイヤーは、手札の半分を切り捨てで選んで捨てる
2. 手番プレイヤーは盗賊を現在と異なる地形タイルへ移動する
3. 移動先に接する相手プレイヤーを1人選び、その資源カードをランダムに1枚奪う。対象がいなければ奪わない

盗賊がいるタイルは、盗賊が次に移動するまで資源を生産しない。

### 6.3 騎士カード

騎士を使う場合も、盗賊移動とランダムな資源略奪を行う。ダイスで7が出た場合と違い、全員の手札破棄は発生しない。使用済み騎士は表向きに残し、最大騎士力の判定に使う。

## 7. 交易

### 7.1 プレイヤー間交易

- 手番プレイヤーだけが、相手プレイヤー1人と資源カードを交換できる
- 交渉は任意の交換比率でよいが、両者とも現在持つ資源だけを出せる
- 資源の無償譲渡、将来の約束、発展カードの交換は許可しない
- 手番でないプレイヤー同士は交換できない

UIでは、提案者・相手・渡す資源の内訳・受け取る資源の内訳を持つ `TradeOffer` を作り、相手の承認でだけ原子的に交換する。

### 7.2 海上交易（銀行）

手番プレイヤーは銀行と次の比率で資源を交換できる。

| 条件 | 交換比率 |
| --- | --- |
| 港なし | 同じ資源4枚 → 任意の資源1枚 |
| 一般港を所有 | 同じ資源3枚 → 任意の資源1枚 |
| 専門港を所有 | 対応する資源2枚 → 任意の資源1枚 |

複数の港を持つ場合は、支払う資源ごとに最も有利な比率を選ぶ。銀行に受け取る資源が残っていなければ、その交易はできない。

## 8. 建設とコスト

建設時は、資源を銀行へ支払ってからコマを配置する。1手番に複数の建設を行ってよい。

| 行動 | コスト | 配置・効果 |
| --- | --- | --- |
| 道を建てる | 木材1、レンガ1 | 自分の道・開拓地・都市に接する空き辺へ置く |
| 開拓地を建てる | 木材1、レンガ1、羊毛1、小麦1 | 距離ルールを満たす空き交点。自分の道に接続が必要 |
| 都市を建てる | 鉱石3、小麦2 | 自分の開拓地を置き換える。開拓地コマは手元に戻る |
| 発展カードを買う | 鉱石1、羊毛1、小麦1 | 山札の一番上を非公開で得る |

相手の開拓地・都市が自分の道の途中に置かれると、その交点をまたいで自分の道を連結したものとして数えない。ただし、自分の建物は自分の道を分断しない。

## 9. 発展カードと特殊カード

### 9.1 発展カード

- **騎士**: 盗賊を移動し、対象からランダムに資源1枚を得る
- **街道建設**: 通常の接続条件を守りつつ、コストなしで道を2本置く。2本目は1本目を利用して接続してよい
- **発見（豊作）**: 銀行から任意の資源を合計2枚得る。同じ種類を2枚選んでもよい
- **独占**: 資源種を1つ選び、相手全員はその資源を全て手番プレイヤーへ渡す
- **勝利点**: 1点。勝利時まで非公開で保持する

発展カード山札が空なら、発展カードは購入できない。使用済みの騎士以外の発展カードは捨て札に移す。

### 9.2 最大騎士力

最初に使用済み騎士を3枚以上持ったプレイヤーが獲得する。別のプレイヤーが現所有者より多くの使用済み騎士を持った時点で移る。同数では移らない。価値は2点。

### 9.3 最長交易路

連続する自分の道が5本以上あり、他の条件を満たす最長のプレイヤーが獲得する。価値は2点。

- 分岐の枝を合算せず、一本道としてたどれる最大の長さで判定する
- 相手の開拓地または都市がある交点では、道の連続が途切れる
- 相手がより長い道を完成させたときだけカードが移る。同じ長さでは現所有者が維持する
- 分断により誰も単独の最長かつ5本以上でなくなれば、一時的に所有者なしとなる

**実装メモ**: 道を辺、交点を頂点とするグラフで、所有者ごとに「辺を重複使用しない最長経路」を探索する。相手建物のある交点は通過禁止にする。この判定は複雑なので、分岐・環状路・相手建物による分断・同率・所有者の維持を単体テストにする。

## 10. アプリの状態モデル

Pythonのゲームエンジンは、画面とは独立して次の情報を持つ。

```text
GameState
├─ board
│  ├─ hexes（地形、数字、盗賊の位置）
│  ├─ vertices（建物、港、隣接情報）
│  └─ edges（道、隣接情報）
├─ players
│  ├─ resources（5種類の枚数）
│  ├─ development_cards（非公開）
│  ├─ played_knights
│  └─ pieces_remaining / victory_points
├─ bank（資源残数、発展カード山札）
├─ turn（手番、フェーズ、使用済み発展カード数）
├─ special_cards（最長交易路、最大騎士力の所有者）
└─ log（イベント履歴）
```

フロントエンドには、プレイヤーごとに見えてよい情報だけを返す。たとえば相手の資源は「内訳」ではなく「合計枚数」、相手の未使用発展カードは「枚数」だけにする。

## 11. フェーズと合法手

フェーズを明示すると、人間UIにもAIにも同じ `legal_actions(state, player_id)` を使える。

| フェーズ | 許可する主な行動 |
| --- | --- |
| `SETUP_FORWARD` / `SETUP_REVERSE` | 初期開拓地、直結する初期道 |
| `TURN_PRE_ROLL` | 発展カード使用（任意）、ダイスを振る |
| `RESOLVE_PRODUCTION` | 自動の資源配布 |
| `DISCARD_FOR_SEVEN` | 捨てる資源を選ぶ |
| `MOVE_ROBBER` | 移動先を選ぶ |
| `STEAL_RESOURCE` | 略奪対象を選ぶ、または対象なしで完了 |
| `ACTION` | 交易、建設、発展カード使用、手番終了 |
| `GAME_OVER` | 行動不可 |

AIには盤面全体と、自分の非公開手札だけを渡す。他プレイヤーの資源内訳や未公開発展カードを渡さない。これは人間とAIの情報量を揃えるために重要である。

## 12. 最初に書くべきテスト

以下はルール実装後、UIより先にPythonで自動テストする。

1. 開拓地を置くと隣接タイルの資源を1枚ずつ生む
2. 都市は資源を2枚生む
3. 盗賊上の地形は生産しない
4. 7で8枚以上の手札だけが正しい枚数を捨てる
5. 距離ルール違反の開拓地を拒否する
6. 道が自分のネットワークに接続していない場合は拒否する
7. 4:1、3:1、2:1の交易比率を正しく選ぶ
8. 購入直後の騎士・進歩カードを使えない
9. 騎士3枚で最大騎士力、より多い騎士で移転する
10. 最長交易路の分岐・同率・分断を正しく判定する
11. 10点以上を自分の手番中に得た場合だけ勝利できる

## 13. 実装の段階分け

最初から全ルールを同時に作らない。

1. **MVP**: 固定盤面、初期配置、ダイス、資源生産、道・開拓地・都市、10点勝利
2. **経済**: 銀行との4:1交易、港、プレイヤー間交易
3. **妨害**: 7、手札破棄、盗賊、ランダム略奪
4. **カードと得点**: 発展カード、最大騎士力、最長交易路
5. **AIと分析**: ランダムAI、ルールベースAI、SQLiteの対局ログ、SQL分析

各段階で「合法手の列挙」と「不正な手を拒否するテスト」を先に作る。これにより、画面操作・AI・APIがすべて同じゲームルールを利用できる。
