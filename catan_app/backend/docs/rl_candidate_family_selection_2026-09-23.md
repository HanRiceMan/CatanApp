# 候補共有型PPO：行動種別を先に選ぶ評価実験

## 目的と方式

候補共有型では、道路全体の確率が高くても複数の辺に分散し、手番終了など単一Actionの確率にargmaxで負ける症状があった。保存済み完成モデルを再学習せず、通常のactionフェーズだけ次の方式で比較した。

1. `global_argmax`：従来通り、合法Action候補の最大確率1個を選択。
2. `family_mass`：道路・開拓地・都市・発展購入・銀行交易・発展使用・手番終了など、行動種別ごとに候補確率を合計。合計最大の種別を選び、その中の最大確率候補を選択。
3. `family_l2`：確率のL2ノルムで種別を選択。候補数が多い種別への優遇を合計方式より弱める中間案。

初期配置やサイコロなど通常actionフェーズ以外は既存PPOAgentの選択を維持した。評価専用であり、UI・通常AI・学習分布は変更していない。

## 既知盤面での完成モデル比較

学習seed `20260923`、`20260924`、`20260925` の完成モデル（実step数10,240）を、既存評価盤面seed `40001`〜`40100`、Heuristic×3、Player IDローテーションで評価した。各方式・モデル100対局、計900対局。非法Action・打ち切り0。

| 学習seed | 方式 | 勝率 | 平均VP | 有料道路 | 追加開拓地 |
| --- | --- | ---: | ---: | ---: | ---: |
| 20260923 | global / mass / L2 | 23% / 21% / 25% | 6.73 / 6.67 / 6.79 | 5.28 / 5.53 / 5.25 | 0.70 / 0.80 / 0.76 |
| 20260924 | global / mass / L2 | 12% / 14% / 13% | 6.50 / 6.75 / 6.61 | 5.98 / 6.60 / 6.45 | 0.93 / 0.99 / 0.99 |
| 20260925 | global / mass / L2 | 2% / 8% / 4% | 4.43 / 5.78 / 5.06 | 0 / 6.46 / 2.70 | 0 / 0.60 / 0.25 |

`family_mass` は弱いseedで道路と開拓地を復活させ、平均VPを+1.35（対応付きbootstrap 95%区間+0.96〜+1.74）改善した。良いseedでは平均VP差−0.06（−0.29〜+0.17）、中間seedでは+0.25（+0.05〜+0.47）。道路だけの極端な増加や銀行交易の増加は見られなかった。L2方式は弱いモデルを一部しか救えなかった。

## 未使用盤面でのholdout検証

方式の判断に使っていない盤面seed `50001`〜`50100` で、`global_argmax` と最も有望だった `family_mass` を再比較した。3モデル×2方式×100対局、計600対局。非法Action・打ち切り0。

| 学習seed | global 勝率 / VP | family_mass 勝率 / VP | 勝率差 / VP差（mass−global） |
| --- | --- | --- | --- |
| 20260923 | 19% / 6.82 | 22% / 6.60 | +3pt / −0.22 |
| 20260924 | 12% / 6.56 | 21% / 6.80 | +9pt / +0.24 |
| 20260925 | 5% / 4.94 | 6% / 5.16 | +1pt / +0.22 |

対応付きbootstrap 95%区間は、seed順に勝率差 `[-5,+11]`、`[+4,+15]`、`[-5,+7]`ポイント、VP差 `[-0.50,+0.05]`、`[+0.06,+0.43]`、`[-0.18,+0.62]`。holdoutでは弱いseedへの改善が小さくなり、良いseedの平均VPは少し低下した。3seedすべてで道路選択は動作し、seed `20260925` では道路0→5.19本、追加開拓地0→0.35軒となった。

## 判断

候補数によるargmaxの希釈は実在し、行動種別の確率合計は症状を解消する。しかし、**推論時だけfamily_massへ変えれば一貫して強くなる、とは確認できなかった**。既知盤面ほどholdoutで改善しなかったため、通常AIやUIへの正式採用は見送る。

次は推論時の補正探索を増やすより、学習時から「行動種別→種別内候補」という確率分解を扱える階層方策を、小さな独立実験として設計する。PPOのlog probability・entropy・Action Maskを正しく保つ必要があるため、既存方策の上書きではなく新しい実験用policyとして追加する。報酬・対戦相手・Observationを同時に変更せず、まず短いsmoke testと複数seed比較を行う。GNNはまだ導入しない。
